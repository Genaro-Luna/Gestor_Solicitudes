# Etapa 3 — Deuda técnica y code smells
**Responsable:** Mathias 

| Nº | Code smell | Evidencia (Fragmento de código) | Ubicación | Impacto | Riesgo | Prioridad |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | **Long Parameter List / Data Clumps** | `public int registrarSolicitud(String legajo, String nombre, String apellido, String email, String tipo, String prioridad, String descripcion)` | `GestorSolicitudes.java` | Agrupa muchos parámetros sueltos en lugar de usar un objeto (ej. EstudianteDTO). Fomenta firmas largas. | Medio (Dificulta la lectura y facilita cometer errores). | Media |
| 2 | **Duplicated Code** | `for (int i = 0; i < lst.size(); i++) { if (lst.get(i).id == id) { s = lst.get(i); } }` | `GestorSolicitudes.java` | Este mismo bloque se repite en asignarResponsable, cambiarEstado y obtener. Además, los métodos buscarPor... repiten la misma lógica de bucle. | Alto (Si cambia la estructura, hay que modificar múltiples métodos). | Alta |
| 3 | **Primitive Obsession / Magic Strings** | `if (!tipo.equals("CERTIFICADO") ...)` y `public String estado;` | `GestorSolicitudes.java` y `Solicitud.java` | Se usa `String` para conceptos del dominio (Estado, Tipo, Prioridad) en vez de `Enums`. | Alto (Propenso a errores de tipeo y sin validación fuerte). | Alta |
| 4 | **Data Class** | `public String legajo; public String nombre;` | `Estudiante.java`, `Solicitud.java` | Son clases anémicas (atributos públicos sin comportamiento). Rompe el encapsulamiento. | Alto (Rompe el ocultamiento de información; cualquier clase altera el estado). | Alta |
| 5 | **Empty Catch Block** | `catch (Exception ex) { }` | `GestorSolicitudes.java` | Se captura una excepción genérica al enviar emails y se ignora por completo. | Medio (Oculta fallas críticas en tiempo de ejecución, imposible debuggear). | Media |
| 6 | **Switch Statements** | `if (op == 1) { ... } else if (op == 2) { ... }` | `Main.java` | El `main` hace de todo: maneja el menú y delega en una cadena gigante de `if/else`. | Alto (Viola SRP; difícil de testear y propenso a romper opciones). | Alta |
| 7 | **Feature Envy** | `long dias = ChronoUnit.DAYS.between(s.fechaCreacion, LocalDate.now());` | `GestorSolicitudes.java` | El Gestor le pide constantemente los datos internos a `Solicitud` para calcular vencimientos. | Medio (La lógica de negocio se fuga hacia el Gestor). | Media |
| 8 | **Dead Code** | `// public void borrarSolicitud(int id) { ... }` | `GestorSolicitudes.java` | Hay código comentado y obsoleto que quedó olvidado en la clase. | Bajo (Solo ensucia la lectura). | Baja |
| 9 | **God Class** | Centraliza listas en memoria, validaciones, creación de objetos, asignación de responsables y notificaciones. | `GestorSolicitudes.java` | Hace de todo. Viola el principio SRP (Responsabilidad Única). | Alto (Cualquier cambio en persistencia, lógica o notificaciones rompe la misma clase). | Alta |
| 10 | **Long Method** | `public int registrarSolicitud(...)` | `GestorSolicitudes.java` | Complica mucho la lectura y el testeo unitario; debería delegar tareas en submétodos. | Alto (Difícil de mantener y propenso a errores). | Alta |
| 11 | **Magic Numbers / Magic Strings** | `if (descripcion.trim().length() < 10)`, `x = 2` y literales como `"CERTIFICADO"`. | `GestorSolicitudes.java` | Usar números y textos sueltos rompe la mantenibilidad. | Medio (Si una regla cambia, hay que buscar ese valor a ciegas en todo el código). | Media |
